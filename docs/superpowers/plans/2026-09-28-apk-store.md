# Apk Store Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a local compressed APK catalog to Frigg with UI and MCP import, listing, deletion, and one-device installation.

**Architecture:** A server-side `ApkStore` owns streaming uploads, metadata, compression, hash verification, and temporary materialization. A loopback-protected API router is shared by the web screen and MCP tools; shared types define the catalog contract, and a packaged skill teaches agents the MCP workflow.

**Tech Stack:** TypeScript, Express, Node streams/zlib/crypto, React, Zustand, MCP SDK, Zod, existing Frigg UI and i18n.

**Spec:** `docs/superpowers/specs/2026-09-28-apk-store-design.md`

## Global Constraints

- Accept one simple `.apk` file per import, with a 1 GiB maximum.
- Stream file bytes; do not buffer APK contents in process memory.
- Store under `~/.frigg/apk-store/` and `~/.frigg/apk-store.json`, using restricted permissions and atomic writes.
- Keep gzip only when it is smaller than the original and verify SHA-256 before installation.
- Install to one authorized, online Android serial with `adb install -r -t` and a five-minute timeout.
- Restrict every Apk Store API route to trusted local UI/loopback access.
- Create `plugin/skills/frigg-apk-store/SKILL.md` and `VERSION` in the same change as MCP tools.
- Do not add install history, batch operations, automatic permissions, downgrade, or split APK support.

## Review Focus

- Interrupted upload, compression failure, and disk-full paths must leave no catalog entries or temporary blobs.
- Concurrent catalog mutations must not lose entries or write stale snapshots.
- A corrupt or modified blob must fail hash verification before ADB receives it.
- Offline/unauthorized devices and same-serial concurrent installs must fail with an actionable result.
- MCP import must stream the explicitly supplied `.apk` path and reject unrelated extensions or files over the size limit.

### Task 2: Local API and Android installation

**Files:**

- Create: `packages/server/src/apk-store/install.ts`
- Modify: `packages/server/src/api/router.ts`
- Modify: `packages/server/src/start.ts`

**Interfaces:**
- `buildApkStoreRouter({ store, apiPort, configuredUiPort })` mounts `GET/POST/DELETE /api/apk-store` and `POST /api/apk-store/:id/install` behind `localUiAccessMiddleware`.
- Import uses a raw `application/octet-stream` request body and URL-encoded `fileName`, `name`, and `description` parameters.
- Install accepts `{ serial: string }`, confirms the serial is currently authorized/online, and returns `{ serial, durationMs, message }`.

- [x] Mount the router with `apiPort: () => deps.apiPort` and the configured UI port.
- [x] Reject invalid metadata, missing or incorrect content type, empty uploads, invalid APK extension/signature, and streams exceeding 1 GiB with 4xx responses.
- [x] Map disk, compression, persistence, device, busy, ADB, and timeout failures to actionable HTTP errors while cleaning temporary data.
- [x] Track active serials in process memory and reject a second install to the same serial with HTTP 409.
- [x] Run `adb -s <serial> install -r -t <temporary-apk>` with the approved 300,000 ms timeout; always remove the materialized APK in `finally`.
